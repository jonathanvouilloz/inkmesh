# Milestone 4 — Agents: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Agents connect to inkmesh through a remote MCP server (OAuth in the browser, or a bearer token) or an HTTP API, and list, read, create, update, replace, move and delete documents with their human's role, signed "<Name> via <agent>"; every write lands in an events table that agents query with a cursor; the editor commits once per editing session.

**Architecture:** Five new `core` modules: `lock.ts` (the per-workspace lock moved out of `documents.ts`), `events.ts`, `sessions.ts` (deferred editor commits, persisted in SQLite), `agents.ts` (agents and tokens), `oauth.ts` (clients, codes, token grants). Adapters stay thin: `src/lib/server/agent-api.ts` (bearer authentication, error mapping, the operations shared by API and MCP), `src/lib/server/mcp.ts` (tools on `McpServer`, served by `createMcpHandler`), `src/lib/server/csrf.ts` (replaces SvelteKit's origin check so cookie-free agent endpoints work). Routes: `/api/v1/...`, `/mcp`, `/.well-known/...`, `/oauth/register`, `/oauth/token`, `(app)/oauth/authorize` (consent), `(app)/[workspace]/-/connect`.

**Tech Stack:** SvelteKit 3.1 (adapter-node), Svelte 5 runes, Node 24 `node:sqlite` and `node:crypto`, git CLI, `@modelcontextprotocol/server@^2.3.1` and `zod@^4.2` (new), Vitest, Playwright.

**Spec:** `docs/plans/2026-10-19-m4-agents-spec.md` (data, tokens, routes, tools, OAuth, sessions, Connect page). Boundaries: `docs/project/architecture.md`. Conventions: `AGENTS.md`. Design: `DESIGN.md`.

## Global Constraints

- Only `src/lib/core/` touches disk, git or the database. Adapters call `core` and map errors through one function, `toApiError` (Task 8): `Forbidden('not a member')` and unknown workspace → 404 `not_found`; `Forbidden('insufficient role')` → 403 `forbidden`; `InvalidPath` → 400 `bad_request`; `InvalidContent('not-utf8')` → 400; `InvalidContent('too-large')` → 413 `payload_too_large`; `Conflict` → 409 `conflict`; `ENOENT`/`ENOTDIR` → 404; anything else rethrown (500, logged, never echoed).
- Error body everywhere outside OAuth: `{ "error": { "code", "message", …extra } }`. OAuth endpoints use RFC 6749 bodies `{ "error", "error_description" }`.
- Tokens: `ink_` + `randomBytes(32).toString('base64url')`; only `hashToken(token)` (SHA-256 hex, from `accounts.ts`) is stored. Never log a token, never read one from a query string.
- Dates are ISO 8601 UTC strings; durations: code 60 s, access 3600 s, refresh 30 days, session idle 60 s.
- The session cookie authenticates pages and form actions only; bearer tokens authenticate `/api/v1` and `/mcp` only.
- Every `core` write runs inside `serialised(slug, …)`, flushes the editing sessions it touches first, commits, then appends exactly one event (none when nothing changed).
- Core modules import each other with relative `.ts` paths; routes use `#lib/...`.
- Every visible string goes through `t(key, locale)` with `en` and `fr`; French uses « » and a non-breaking space before `:` `;` `?` `!`. Commands, JSON, URLs and tokens are never translated and use Fragment Mono.
- New runtime dependencies: `@modelcontextprotocol/server@^2.3.1` and `zod@^4.2`, nothing else.
- Tests run on a temp `INKMESH_DATA` with `closeDb()` in `afterEach` (see `save.test.ts`); e2e on `.data-e2e`.
- Code, comments and commits in English; Conventional Commits; one change per commit; branch `m4-agents`.

## Review Focus

1. A server restart (crash or deploy) while a human has uncommitted editor changes must commit them at the next start, with that human as author, not lose them or commit them as someone else (Task 3 test `recovers sessions after a restart`).
2. An agent writing a document that a human is editing must first commit the human's session under the human's name, then its own commit; the two authors never share a commit (Task 3 test `commits the open session before another author writes`).
3. An authorisation code replayed, exchanged with a wrong verifier or redirect URI, or for another resource must fail with `invalid_grant`, and a replay must not succeed even once (Task 6 test `a code works once and only with its verifier`).
4. A revoked agent must lose access at once: its bearer token, its access token and its refresh token (Task 5 test `revoking an agent kills its tokens`, Task 6 test `a revoked agent cannot refresh`).
5. Turning off SvelteKit's built-in origin check must not open the form actions to cross-site posts (Task 7 test `refuses cross-site form posts outside the agent endpoints`).

### Task 6: OAuth clients, codes and token grants

**Files:**
- Create: `src/lib/core/oauth.ts`, `src/lib/core/oauth.test.ts`

**Interfaces:**
- Consumes: `db()`, `transaction`, `newToken`, `hashToken`, `newAgentToken`, `agentName` (Task 5).
- Produces:
  - `class OAuthError extends Error { code: 'invalid_request' | 'invalid_client' | 'invalid_grant' | 'unsupported_grant_type' | 'invalid_target' | 'invalid_redirect_uri' | 'invalid_client_metadata' }` — constructor `(code, message)`.
  - `type OAuthClient = { clientId: string; name: string; redirectUris: string[] }`
  - `type TokenResponse = { access_token: string; token_type: 'Bearer'; expires_in: number; refresh_token: string }`
  - `registerClient(meta: unknown): OAuthClient` — spec rules (1–5 URIs, ≤ 512 chars, `https:` or loopback `http:`, no fragment; name ≤ 100, default `'MCP client'`); `clientId = crypto.randomUUID()`; deletes clients older than 24 h with no agent.
  - `oauthClient(clientId: string): OAuthClient | null`
  - `redirectAllowed(client: OAuthClient, uri: string): boolean` — exact match, or both `http:` loopback (`localhost`/`127.0.0.1`, same host) with equal path and query, port ignored.
  - `issueCode(input: { clientId: string; redirectUri: string; codeChallenge: string; resource: string; userId: number; agentName: string }): string` — reuses the user's agent with `oauth_client_id = clientId` (renaming it) or creates one; stores the code hash, expiry now + 60 s; deletes expired codes.
  - `exchangeCode(input: { code: string; clientId: string; redirectUri: string; codeVerifier: string; resource?: string }): TokenResponse` — one transaction: find by hash and delete; then `invalid_grant` unless unexpired, same client, same redirect URI, `resource` absent or equal, and `createHash('sha256').update(codeVerifier).digest('base64url') === code_challenge`.
  - `refreshTokens(input: { refreshToken: string; clientId: string; resource?: string }): TokenResponse` — one transaction: the `refresh` row must exist, be unexpired, belong to an agent whose `oauth_client_id = clientId`, match `resource` when sent; deleted, new pair issued.
  - Issuing a pair: an `access` token (`expires_in` 3600) and a `refresh` token (30 days), both with the code's `resource`; expired tokens deleted.
