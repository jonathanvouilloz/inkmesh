# Milestone 3 — Managing files: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Editors bring their own `.md` files into a workspace by dragging them from the computer (or with a file picker), organise them in folders (create, rename, move, delete), and anyone who can read a document downloads it; opening a folder shows its contents.

**Architecture:** Five new `core` functions in `documents.ts` (`createFolder`, `importDocument`, `movePath`, `deletePath`, plus `modified` and empty folders in `listTree`), each one git commit under the existing per-workspace lock. The workspace page gets four form actions that call them; a `+server.ts` route serves the raw file. In the browser, a folder path renders a folder view instead of the editor, a `FileActions` menu carries rename, move, delete and download, and native HTML5 drag and drop on the tree and the folder view imports files from the computer or moves items.

**Tech Stack:** SvelteKit 3 (adapter-node), Svelte 5 runes, Node 24, git CLI, Vitest, Playwright. No new dependency.

**Spec:** `docs/project/prd.md` items 2 (folder view) and 3 (managing files). Boundaries: `docs/project/architecture.md`. Conventions: `AGENTS.md`. Design: `DESIGN.md`.

## Global Constraints

- Only `src/lib/core/` touches disk or git; routes map `Forbidden` to 403 / non-membership to 404 (through `requireRole`), `Conflict` to 409, `InvalidPath` to 400, `InvalidContent` to 400 (`not-utf8`) or 413 (`too-large`), `ENOENT` to 404.
- Every `core` document function takes an `actor` and calls `assertRole` first: `reader` for reads and download, `editor` for every write.
- Every write runs inside `serialised(slug, …)` and ends in exactly one `gitCommit` (or none when nothing changed); on commit failure the disk is put back as it was.
- Commit messages: `Create folder <p>` is never committed (git does not track empty folders); `Import <p>`, `Replace <p>`, `Move <from> to <to>`, `Delete <p>`. Author: `commitAuthor(actor)`.
- Imported documents: UTF-8 Markdown, at most `MAX_DOCUMENT_BYTES = 3 * 1024 * 1024` bytes, stored byte for byte. Accepted file names end in `.md` or `.markdown` (case-insensitive); `.markdown` is stored as `.md`.
- A folder name never ends in `.md` and no path segment starts with `.`, so a URL path ending in `.md` is always a document and any other path is a folder.
- Links follow a move: in the same commit, every relative link or image URL in the workspace's documents that pointed into the moved item, and every relative URL inside a moved document, is rewritten to the new location; only the URL characters change, every other byte stays. The move and rename dialogs say how many other documents will be updated. Absolute URLs (`scheme:`, `/…`, `#…`) are never touched.
- Every visible string goes through `t(key, locale)` with `en` and `fr` entries; French uses « » and a non-breaking space before `:` `;` `?` `!`.
- Interactive controls are reachable with the keyboard: drag and drop is a shortcut, never the only way (the "Move to…" menu and the file picker cover both).
- Code, comments and commits in English; Conventional Commits; one change per commit; branch `m3-files`.

## Review Focus

1. A document open in someone's editor is moved or deleted by someone else: their next autosave must show the conflict state, never recreate the file at the old path (Task 4 test `a write after a move is a conflict`).
2. A folder moved into itself or into one of its own subfolders must be refused, not loop or vanish (Task 4 test `refuses to move a folder into itself`).
3. Dropping files that already exist must ask before replacing, and replacing must keep the previous version in history (Task 3 test `replaces only with overwrite and keeps history`; Task 8 e2e `asks before replacing`).
4. A dropped folder, an image or a 0-byte directory entry from the OS must be reported per file and not abort the other files in the same drop (Task 6 test `reports each file of a mixed import`).
5. A document or folder that was never committed (written by an agent with plain `cp`, or an empty folder) must still move and delete without a git error (Task 1 test `ignores paths git does not know`).

### Task 4b: Links follow a move

**Files:**
- Modify: `src/lib/core/markdown.ts`, `src/lib/core/documents.ts` (`movePath`, new `linksTo`)
- Test: `src/lib/core/markdown.test.ts`, `src/lib/core/documents.test.ts`

**Interfaces:**
- Produces: `rewriteUrls(source: string, rewrite: (url: string) => string | null): string` in `markdown.ts` — parses with the shared remark configuration, visits `link`, `image` and `definition` nodes, and for each one whose `rewrite(url)` returns a different string replaces only the URL's characters in `source` (located from the node's position offsets), keeping title, brackets and angle-bracket form; returns `source` unchanged when nothing changes. Frontmatter is untouched.
- Produces: `relocate(url: string, oldDoc: string, newDoc: string, moved: { from: string; to: string }): string | null` in `documents.ts` (exported for tests) — `null` for absolute URLs (`/^[a-z][a-z0-9+.-]*:/i`, leading `/`, leading `#`); otherwise splits off `?…`/`#…`, percent-decodes the path, resolves it against `dirname(oldDoc)`, maps a target equal to or under `moved.from` to `moved.to`, makes it relative to `dirname(newDoc)`, re-encodes each segment with `encodeURI` semantics (spaces → `%20`), re-appends the suffix; `null` when the result equals the input.
- Produces: `linksTo(slug: string, path: string, actor: Actor): Promise<string[]>` — role `reader`; the documents outside `path` that hold at least one relative URL resolving to `path` or under it (the dialogs show its length).
- Changes: `movePath` rewrites, inside its lock and before its commit, every document whose content changes under `rewriteUrls(source, (u) => relocate(u, oldPathOfDoc, newPathOfDoc, { from, to }))`, and adds those paths to the commit's `paths`; on commit failure the rewritten files are restored with the move.
