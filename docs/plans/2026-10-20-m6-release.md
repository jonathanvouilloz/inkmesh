# Milestone 6 — Release: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Members sort and filter a folder by its documents' frontmatter through a shareable URL (public workspace links too), sign in with an emailed link, send invitations by email, get an opt-in daily digest they can stop in one click, and anyone can self-host inkmesh from the README with Docker under the MIT licence.

**Architecture:** `core` gains `frontmatterFields` (in `markdown.ts`), `folderFields` / `sharedFolderFields` (per-folder frontmatter read), `mail.ts` (configuration, transports, the three message builders), login links in `accounts.ts`, `pendingDigest` in `inbox.ts`, and `digest.ts` (setting, daily slot, run, timer, unsubscribe tokens). A pure `src/lib/ui/folderQuery.ts` turns URL parameters into the folder's sorted and filtered list. Routes: the four folder loads, `/login` (actions `password` and `link`), `/login/link/<token>`, `/account?/digest`, `/unsubscribe/<token>`, the members `invite` action. `init` checks the email configuration and starts the digest timer. A Dockerfile, a compose example, the README and the LICENSE close the release.

**Tech Stack:** SvelteKit 3.1 (adapter-node), Svelte 5 runes, Node 24 (`node:sqlite`, `node:crypto`, `node:net` in one test), git CLI, `nodemailer@10.0.15` (new, exact), Vitest, Playwright, Docker (`node:24-bookworm-slim`).

**Spec:** `docs/plans/2026-10-20-m6-release-spec.md` (rulings, decisions, data, environment, emails, routes, interface, security rules). Boundaries: `docs/project/architecture.md`. Conventions: `AGENTS.md`. Design: `DESIGN.md`.

## Global Constraints

- Only `src/lib/core/` touches disk, git, the database or the mail transports (the `file:` transport writes under `$INKMESH_DATA/mail/` only). Every `core` function that reads workspace content takes an `actor` and calls `assertRole` (`reader` for `folderFields`), except the `shared*` functions, whose check is the link's scope.
- Email is on only when `SMTP_URL`, `MAIL_FROM` and `INKMESH_URL` are all set; partial or invalid configuration stops the start. Every link in an email starts with `INKMESH_URL`, never the request's origin. No real email is sent while building: unit tests use `SMTP_URL=memory:`, e2e uses `SMTP_URL=file:`, and no task sets an `smtp://` or `smtps://` URL pointing anywhere but a fake server on `127.0.0.1` inside a test.
- Tokens: login links `newToken()` stored as `hashToken(token)`, 15 minutes, single use; unsubscribe tokens `<id>.<base64url HMAC-SHA256>` with the `instance_keys` key, compared with `timingSafeEqual`. No token, email address or link URL is logged.
- No state change on a GET: login links and unsubscribe act on POST only.
- Throttles (the existing in-memory `loginAllowed(key, max)` / `loginFailed(key)`, 15 minutes): `link-ip|<ip>` 10, `link-email|<normalized email>` 3, `invite-mail|<user id>` 20.
- Limits: login link 15 minutes; digest 50 lines; filters 5, filter value 200 characters; 30 field names and 50 values per field in the query bar; `DIGEST_HOUR` 0–23, default 8.
- Sort and filter: reserved parameters `sort`, `order`, `field`, `value`; no new dependency; no YAML parser.
- One new runtime dependency: `nodemailer@10.0.15`, exact pin (it ships its own types). Nothing else.
- Every visible string, email text included, goes through `t(key, locale)` with `en` and `fr`; French uses « » and a non-breaking space (U+00A0) before `:` `;` `?` `!` and inside guillemets. Paths, emails, field names, values, hashes and times use Fragment Mono.
- Core modules import each other with relative `.ts` paths; routes use `#lib/...`. `core/mail.ts` and `core/digest.ts` may import `../i18n/index.ts` (pure).
- Tests run on a temp `INKMESH_DATA` with `closeDb()` in `afterEach`, and delete every mail variable they set; e2e on `.data-e2e`, new specs in their own folders (`e2e-query/`, …) or on their own account state, cleaned in `afterEach`.
- Code, comments and commits in English; Conventional Commits; one change per commit; branch `m6-release`.

## Review Focus

1. A mail scanner or link preview that GETs a sign-in link must not use it, and asking for a link must not reveal whether an account exists, by text, status or timing (Task 6 tests `the landing GET never consumes the link` and `known and unknown addresses get the same answer`).
2. A forged `Host` header on the link request must not put the attacker's host in the emailed URL (Task 6 test `the emailed link ignores the request host`).
3. The digest must neither repeat nor lose events across restarts, failed sends and the slot boundary (Task 8 tests `catch-up is idempotent`, `a failed send is retried at the next slot`, `events after the slot wait for the next one`).
4. Odd files in a folder (no frontmatter, an unclosed `---`, CRLF, a non-UTF-8 file, a malformed list) must never break the folder view; they simply have no field (Task 1 test `odd files have no fields and break nothing`).
5. A broken mail setup must be loud at start and quiet at runtime: a partial configuration stops the process with the variable's name; an unreachable SMTP server leaves the link request's answer unchanged and the invitation link on screen (Task 4 test `refuses a partial configuration`; Task 6 test `a failed send changes nothing for the visitor`; Task 7 test `a failed email keeps the link`).

**Interfaces:**
