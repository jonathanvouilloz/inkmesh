# UX polish after first real use — plan

**Goal:** Fix the four frictions Jon met on inkmesh.ch on 2026-10-20: an invited person types an email we already know; creating a workspace is hard to find; pages are too narrow, so lines and button rows wrap; the members page mixes invitations and public links, its buttons do not line up, and a newly created link does not stand out.

**Branch:** `ux-polish`. Same rules as the milestones: `core` alone touches disk, git and the database; UI strings fr+en through `t()`; French « » and NBSP; the round-trip tests stay as they are; e2e on `.data-e2e`.

## Current state (read in the code, 2026-10-20)
- `invitations` has no email column (`src/lib/core/db.ts`); the members `invite` action mails the link but forgets the address, so `/invite/<token>` cannot fill it in.
- Only the home page (`/`) creates a workspace, in a `<details>` "New workspace" shown to instance admins. The header switcher (`Header.svelte`) lists the workspaces and nothing else; the workspace's left rail has no way there.
- Every page column is `max-width: 72ch` (about 580px at 13px chrome): members, connect, account, inbox, search, history, home, the folder view and the public pages, each in its own `<style>`. The document column is also 72ch of 16.5px text.
- Members page, top to bottom: members table (role select + "Save", then "Remove" in another cell), pending invitations, "New invitation link" (role + "Create link", and the email field when email is on), public links (table, then a create form whose "Covers" select is wider than the table above it). The one-time link appears under its form, with a focus ring only.
- The header search covers the current workspace (titles and text), not every workspace.

## Tasks

### Task 1: Invited email filled in at sign-up
- Migration `006-invitation-email`: `ALTER TABLE invitations ADD COLUMN email TEXT` (null for link-only invitations; existing rows stay null).
- `createInvitation` takes an optional email; the members `invite` action passes the address it mails. `invitation(token)` returns it.
- `/invite/<token>`: `SignupForm` gets the invitation's email as its default value (a failed submit keeps what was typed). The field stays editable: the person may prefer another address. A signed-in visitor still sees "Join".
- Tests: core (stored, returned, null without email); route (the mailed invitation page shows the address; the link-only one shows an empty field); e2e on the invite flow with `SMTP_URL=file:`.
- Prod: copy-test migration 006 on a copy of `~/inkmesh-data` before deploying (forward-only, one nullable column).

### Task 2: A visible way to create a workspace
- Header switcher: after the workspace list, a separator and "+ New workspace" for instance admins, linking to `/?new`. The home page opens its create form when `new` is in the URL and focuses the name field.
- Nothing for non-admins (only admins can create a workspace, PRD). No second button elsewhere: the switcher is where Jon looked for it.
- Phones: the switcher already holds the list; the item appears there the same way.
- Tests: e2e (admin sees the item and lands on the open form; a member does not see it).

### Task 3: Wider pages
- One token in `src/app.css`, `--page-width: 1040px` (about 1.8× today), replacing the 72ch of every management page and of the folder view and public folder pages; each column stays centred, with its side padding (32px desktop, 16px phone).
- Documents (editor, version view, public document) keep a reading width but widen from 72ch to `--doc-width: 760px` (Jon chose 760px on 2026-10-20). Rendered text wider than that tires the eye.
- Recheck every page at 1440, 1024 and 390px: no horizontal scroll, button rows on one line at desktop width.
- `DESIGN.md`: the two widths and where each applies.

### Task 4: Members page, clearer
- Order: Members · Invite someone · Pending invitations · Public links. A one-line description under "Invite someone" ("For a person who will have an account") and under "Public links" ("Read-only, without an account") so the two are not confused.
- Tables: a fixed actions column aligned right; "Save" sits next to the role select, "Remove" in the actions column; the same layout in the public-links table. The create forms line up with the table above (same column width, controls on one line at desktop width).
- New link: the one-time link shows in a highlighted panel (accent left border, light accent ground, "New link" title), receives the focus and is announced; the matching new row in the table is highlighted for a few seconds (no animation when reduced motion is asked).
- Tests: existing members e2e updated to the new headings; a check that the new-link panel has the focus.

### Task 5: Verification and delivery
- `npm test`, `svelte-check`, full e2e; screenshots before/after (fr and en, desktop and phone) in `design/shots/ux-polish/`; `review-ui` on the members page and the header menu; French copy reread.
- Merge into `main`, backup `~/inkmesh-data`, copy-test migration 006, `scripts/deploy.sh`, smoke test on https://inkmesh.ch.

## Not in this plan

- Locking the invited email (the field stays editable).
